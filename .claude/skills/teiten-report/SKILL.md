# TEITEN デイリーレポートの作成

金融系メディア TEITEN（定点）の日次レポートを、データ収集から公開まで通しで行う。

**このスキルは `money-flow-report` スキルの分析フレームを、TEITEN のコンテンツ形式に落とすためのもの。**分析の枠組み（資金移動を矢印で表す、結論ファースト、表を使わない）は `money-flow-report` に従い、出力先と書式はこちらに従う。

## 前提

- リポジトリ直下（`D:\OneDrive\01_仕事・事業\M16BIZ\financial-report`）で作業する
- 構造・設計の判断は `docs/SPEC.md` が正。迷ったらそちらを見る
- 日付・時刻はすべて JST

## 手順

### 0. 出す日かを確認する

```bash
python tools/should-run.py
```

`休止` と出たら、**記事を書かずにそこで終える。**終了コードは 10。

判定の考え方は次のとおりで、詳細はスクリプトの冒頭に書いてある。

- **日本だけの祝日** … 米国は動いている。**出す**（秋分の日など）
- **直前の平日が米国休場** … 扱う新しいセッションが無い。**出さない**
- **12/29〜1/3** … 市場と無関係に休む。1/4 から再開

日本の祝日表は持っていない。判定に影響しないためである。

### 1. 雛形を作る

```bash
python tools/new-report.py            # 本日分
python tools/new-report.py 2026-09-24 # 日付指定
```

号数は自動で振られる。**手で付けない。**土日を指定すると警告が出るので、その場合は日付が正しいか確認する。

### 2. データを集める

**まず FRED から取る。検索より先にこれを実行する。**

```bash
python tools/fetch-indicators.py
```

実質金利（TIPS10年）・VIX・米2年/10年/30年・S&P 500・期待インフレ率・米ハイイールド債スプレッドが一度に出る。
続けて、金（USAGOLD、`tools/fetch-gold.py`）と、**ドル指数・日経225・日経VI・WTI・Brent・Nasdaq・ダウ・
銀・プラチナ・銅・MOVE の確定した日足終値**とドル円・ユーロドルのニューヨーク17時の値（Yahoo Finance、`tools/fetch-market.py`）、
**日本10年債（財務省）・BTC（CoinGecko、UTC 0:00）・BTC現物ETFの資金フロー（Farside）**（`tools/fetch-extra.py`）も出る。

**日次の snapshot・ティッカーの8項目は変えない**（2026-10-27）。銀・プラチナ・銅・MOVE・HYスプレッドは
本文で数値を添えるために取る。「銀・プラチナもそろって下げた」と書くなら、その値と変化率を書く。
週次はこれらを `tools/fetch-weekly.py` で週単位に集計する。

**8時の実行で出る値の範囲**：

- 日経225・日経VI・S&P 500・Nasdaq・ダウ・VIX … **前営業日の終値**が出る
- ドル指数・WTI・Brent・金先物 … 確定した終値は**前々営業日**まで。前営業日は「読み取り」
  （ニューヨーク時間の時刻つきの取引中の値）で出る。Yahoo の日足はニューヨークの0時まで確定しないため

**「◯/◯終値」の行と、報道の同じ定義の値が食い違ったら、スクリプトの値を採る。**
報道どうしが割れていても「決められないので未確認」にはしない（`docs/SOURCES.md` §1）。
ドル指数が報道の寄せ集めで2日続けて未確認になり、自動公開が止まったため。

**「読み取り」は終値ではない。**前営業日の WTI・Brent の清算値は、従来どおり報道を複数社で突き合わせて取る。
ドル指数の前営業日の終値も報道から取り、報道が割れたら、読み取りの値を**時刻つきで**載せる
（「102.55（10/14 18:04 NY時点）」。金の USAGOLD 読み取りと同じ扱い）。前々営業日の終値は確定値として使えるので、
前号で未確認にした値や、報道で割れた値の答え合わせに使う。

これらは**報道記事が「今日の値」として書かない指標**なので、ニュースを検索しても出てこない。実質金利が9本中7本で「未確認」のまま残っていたのは、探し方が違ったためである。

出力は `実質金利（TIPS10年）：2.90%（9/28時点、FRED DFII10）` の形で出る。**「◯/◯時点」を落とさずに本文へ書く。**系列によって1〜2営業日の遅れがあり、日付が無いといつの値か分からなくなる。**遅れを理由に空欄にしない。**翌号で確定値に差し替える。

取得元の一覧と原則は `docs/SOURCES.md`（公開版は `/sources/`）。**取得元を変えたら両方を直す。**

#### スクリプトから通信できなかった場合

実行環境が外向き通信を塞いでいることがある（クラウドの定期実行で実際に起きた）。**ここで諦めて「未確認」にしない。**スクリプトが代替手順とURLを出すので、それに従う。

1. 出力されたURLをWeb取得ツールで開く
2. **要約された文章から数字を読まない。**保存された生ファイルを開き、`YYYY-MM-DD,値` の行をそのまま読む
3. 日付が平日で、直近5営業日以内であることを確かめる
4. それでも生の行を確認できなければ「未確認」と書く

**要約を通すと数値が作られる。**実際に、存在しない土曜日（2026-09-26）の行を含む出力が返ったことがある。生データには無い行だった。同じ取得で、正しい値（9/29, 2.91）と架空の行が混在していた。

この媒体は「数値を創作しない」を最上位の規則にしている。**要約の出力は、人が書いた記事と同じく裏を取る対象**であって、一次データではない。

スクリプトに無いもの（Fed 高官発言・材料）と、
スクリプトが取れなかった指標はウェブ検索で補う。`money-flow-report` スキルの `references/search-strategy.md` に従う。最低限、次を押さえる。

**必ず取る（snapshot の8項目）**

XAU/USD（現物）／ドル指数 DXY／米10年債利回り／実質金利 TIPS10年／WTI原油／S&P 500／日経225／BTC

**金の値は `fetch-indicators.py` が出す USAGOLD 価格履歴の値を使う**（`tools/fetch-gold.py`）。
報道の値を寄せ集めない。出所ごとに割れるのが常で、系列を固定しないと毎朝ぐらつく。
取れなかったら「未確認」と書く。

**本文で使う追加データ**

- **金利の多層**：米10年に加えて**米2年・日本10年・実質金利**。1本だけだと実質金利の分解ができない
- **株の内訳**：S&P 500・Nasdaq総合・ダウ・日経225。指数間の差が金利感応度を示す
- **Crypto**：BTCの水準とETF資金流入。**金との対比が論点**になる。どちらも `fetch-extra.py` の値を使う
- **Volatility**：VIXと日経VI。内外の温度差を見る。米国債が震源の日は MOVE も添える
- **貴金属と銅**：銀・プラチナ・銅（`fetch-market.py`）。金だけが動いたのか、商品全体が動いたのかの判別に使う
- **クレジット**：米HYスプレッド（FRED、1〜2営業日遅れ。日付を添える）。株安がローテーションか本当のリスクオフかの判別に使う
- **テクニカル・レベル**：移動平均線、直近高安、節目。`levels` に構造化して入れる
- Fed高官発言、経済指標、地政学ヘッドライン

**それでも取れない指標は「未確認」と明記する。**推測で埋めない。

### 2-B. 前号の答え合わせを書く

前号の `Next Flow` のシナリオを読み、**どれが起きたかを frontmatter の `review` に記録する。**

```yaml
review:
  of: "2026-09-29"
  verdict: partial          # hit / partial / miss / pending
  scenario: "シナリオB：米・イランの交渉が再開する → …"
  note: "経路は想定どおり。ただし起点は交渉再開ではなくサウジの輸出再開で、水準も届いていない。"
```

毎号シナリオを出しておきながら検証しなければ、出しっぱなしになる。「結論だけを配る媒体にはしない」と掲げている以上、自分の見立ても記録に残す。

- **当たった回だけ書かない。**外れた回も同じ形式で残す。そうしないと記録として成立しない
- `partial` を使うことをためらわない。**二択にすると「方向は合ったが経路が違った」が hit に寄る**
- `scenario` は前号の見出しをそのまま引く。あとから言い換えると検証にならない
- まだ判定できないなら `pending`。無理に決めない

履歴は `/review/` に自動で並ぶ。

**対象期間の切り分け**：D日のレポートは、原則として **D-1日の米国セッション**を扱う。D日の朝（JST）時点で確定しているのはそこまでのため。前号と同じ値動きを二重に書かない。

### 3. データを検証する

**ここが一番事故が起きる。**

- **複数ソースで突き合わせる。**矛盾したら、より具体的で日付が明記されたソースを採る
- **矛盾したまま採用しない。**過去に、金2,048ドル・DXY 103.45 という他の全ソースと食い違う値を返すサイトがあった。そういうソースは捨てる
- **取れなかった指標は「未確認」と書く。**推測で埋めない。要点にも明記する
- **出所の違う数値を並べない。**現物と先物を混ぜるなら、どちらがどちらか本文で明示する

### 4. 本文を書く

雛形の節構成に沿って埋める。`money-flow-report` の当日フォーマットと同じ骨格。

**frontmatter の要点**

| 項目 | 注意 |
|---|---|
| `title` | 資産名・価格・方向感を主役に。ニュース見出しではなく市場データのヘッドラインとして |
| `deck` | 120〜180字。TOPのヒーローと一覧の抜粋に出る |
| `points` | 3〜5件。取れなかった指標があればそれも要点に入れる |
| `snapshot` | 8件。`dir` は up / down / flat |
| `levels` | **テクニカル・レベル。定点観測の中核。**上から下へ価格順。`kind` は resistance / current / support。`current` を必ず入れる |
| `headline` | 通常は XAU/USD の変化率 |
| `description` | **80〜100字。必ず書く。**未記入だと `deck` が流用され一覧で重複する |
| `tags` | トピック索引に使われる |

**本文の節構成（12節すべて埋める）**

```
## Macro Theme              その日の核心を1〜2段落＋資金フロー行
## Market Drivers           ①②③ それぞれ数値つき、末尾に「→」で帰結
## 金利（起点）             米10年・米2年・日本10年・実質金利 → 解釈 → 資金 → 情報元
## ドル                     DXY・USD/JPY → 解釈 → 資金 → 情報元
## 商品                     WTI・Brent・金 ／ Macro Drivers（三軸）／ 資金フロー結論 → 情報元
## 株                       S&P・Nasdaq・ダウ・日経 → 解釈 → 資金 → 情報元
## Crypto                   BTC。実質金利・Nasdaqとの連動、金との対比
## Volatility               VIX・日経VI。内外の温度差
## 今日の資金フロー         総括の連鎖を太字1行 ＋ 3〜5行 ＋ 「→ 総括：」
## マーケットポジション     中期の歪み
## Next Flow（短期）        シナリオA/B/C。各々「→」で因果連鎖
## Market Bias（短期）      スタンス1行＋監視項目3つ
```

**節を省略しない。**日によって読める情報が変わると、定点観測にならない。データが取れなかった節は「未確認」と書いて残す。

**各セクションに情報元を付ける。**金利・ドル・商品・株は最低限必要。

**本文の決まりごと**

- 見出しは `##` から（`#` はタイトルが使う）
- 表（table）を使わない
- 資金移動は `資金　A → B` と書く。remark プラグインがフロー表示に変換する
- 因果連鎖は `→ A → B → C。補足` と書く。最初の句点以降が注記欄に落ちる
- 本日の総括は段落全体を太字にする（`**原油 → 米国債 → ハイテク株**`）
- **出典は必ずリンク付きリスト**。素のURL列挙は1段落に潰れる

```markdown
情報元：

- [CNBC（Fed rate decision、2026/09/16）](https://www.cnbc.com/...)
```

- 遡って書く場合は、**遡及作成である旨を本文冒頭に明記する**（雛形が自動で入れる）。判断の過程を記録する媒体で、後から書いたものを当日配信したように見せない

### 5. 検査する

```bash
python tools/check-report.py
```

エラーが出たら直す。警告は内容を見て判断する。`draft: true` の警告は、公開前に `false` にすれば消える。

### 6. ビルドして確認する

```bash
npm run build
```

記事を**削除**した場合や、`remark-flow.mjs` / `astro.config.mjs` を触った場合は、先にキャッシュを消す。`.astro` だけでは足りない。

ビルドの最後に `tools/check-html.mjs` が走り、出力された HTML の可視テキストにアスタリスクが無いことを確認する。**警告のみでビルドは止まらない**（公開が最優先。記事が出ないことのほうが損失が大きい）。`NG` が出たら直して push し直す。

日本語は句点のあとに空白を置かないため、`**……である。**次に` のような書き方は CommonMark の規則で強調を閉じられず、記号がそのまま表示される。`remark-strong-fix.mjs` が救済するので**執筆側で気にする必要はない**が、検査が落ちたときはこの理由を疑う。

```bash
rm -rf .astro dist node_modules/.astro node_modules/.vite
```

ブラウザで見るなら `preview_start` で `m16-daily` を起動する。

### 7. コミットして push

```bash
git add src/content/reports/YYYY-MM-DD.md
git commit
git push origin main
```

**`git add -A` を使わない。**ユーザーが並行して同じリポジトリを触ることがあるため、変更したファイルを明示する。

push すると Cloudflare Pages が自動でビルド・デプロイする。

### 8. note用の簡易版を書き出す

note を入口にサイトへ送客する。`note/YYYY-MM-DD.md` に置く
（`src/content/` の外なのでビルドには含まれない）。

**線引き**

| note に出す | サイトに残す |
|---|---|
| 結論（今日の資金フロー） | 金利の多層（米2年・日本10年・実質金利） |
| スナップショットの数字 | ゴールドの三軸とテクニカル・レベルの全段 |
| その日の論点を2つまで | Crypto / Volatility |
| Market Bias と監視項目 | Next Flow のシナリオA/B/C |
| | 出典リンク |

**読み応えのないティーザーにしない。**数字と結論は出し切り、
そこに至る分解の過程をサイトに残す。そうしないと note 側が
「読む価値がない」と判断され、送客そのものが成立しない。

分量はサイト版の3〜4割を目安にする。

**note 側の書式制約**

- 表（table）を使わない。すみつき括弧も使わない
- 見出しは `##` / `###`、区切りは `---`
- 冒頭に大・中・小の3タイトルを置く
- 末尾にハッシュタグ
- **免責を必ず入れる。**個別の売買推奨はできない

末尾にサイトへのリンクと、そこで読めるものの箇条書きを置く。

```
https://teiten.trade/reports/YYYY-MM-DD/
```

書き上げたら、本文をそのままチャットに出力する（note は手動コピペ運用のため）。

### 8-B. note用のサムネイルを書き出す

frontmatter の `thumb` に文言を書き、スクリプトで画像にする。

```bash
node tools/make-thumb.mjs YYYY-MM-DD   # → note/thumb_YYYYMMDD.png（1280×670）
```

| 項目 | 内容 | 長さ |
|---|---|---|
| `title` | 大タイトル。その日の一番の出来事 | 全角15字相当まで |
| `sub` | 中タイトル。二番目の論点と金の位置 | 全角24字相当まで |
| `bias` | 小見出し。Market Bias を1行で | 全角28字までが原寸。42字が上限 |
| `notes` | 数値5枠の寸評（`xau` / `nikkei` / `wti` / `dxy` / `us10y`） | 各8字まで |

半角の英数字は全角の約半分で数える。note 冒頭の大・中タイトルと同じ内容でよいが、
**長さはこちらの枠に合わせて詰める。**

- **数値を `thumb` に書かない。**日付・更新時刻・数値5枠の値と変化率は
  `date` / `updated` / `snapshot` から取る。見出しの中に数字を書くのは構わないが、
  本文と同じ値にする
- 収まらない文言は**エラーで止まる**（何字削ればよいかが出る）。縮小して収めた行は
  「注意」として出る。大タイトルと中タイトルに「注意」が出たら、縮めたままにせず文言を詰める
- 画像は `note/thumb_YYYYMMDD.png`。原稿と一緒にコミットする

**週次も同じスクリプトで出す。**`node tools/make-thumb.mjs YYYY-wNN` →
`note/thumb_YYYYwNN.png`。日付の位置には対象期間が入り、数値5枠は `performance` の
金・日経225・WTI・DXY・米10年の行から取る（変化率は週間の値）。`thumb.bias` は
frontmatter の `bias`（来週のスタンス）を1行に詰めたものにする。
**来週の予定に無い指標やイベントを書かない**（`schedule` にあるものだけ）。

### 8-C. note用の図解を書き出す（日次・週次）

note の本文に貼る縦長の図解（幅1080、高さは内容しだいで約3,100）。frontmatter の
`infographic` に文言を書き、スクリプトで画像にする。

```bash
node tools/make-infographic.mjs YYYY-MM-DD   # → note/info_YYYYMMDD.png
```

**数値は二重に書かない。**各ブロックの項目は `ref`（`snapshot` か `infographic.quotes` の
label の部分一致）で値・変化・向きを引く。`snapshot` に無い数字だけを `quotes` に1回書く。
`quotes` の数字も本文と同じ値にする。出所の無い数字を図解のために足さない。

| 項目 | 内容 |
|---|---|
| `flow` | 冒頭の帯。3〜4枠。`{ text, tone }`。tone は up / down / blue / gold / navy。`\n` で2行 |
| `quotes` | snapshot に無い数値（米2年債・Nasdaq・ダウ・個別銘柄など）。snapshot と同じ形 |
| `focus` | その日の主役の指標。`title` `lead`、予想と結果の `compare`（`label` `unit` `forecast` `actual` `suffix`、2枠まで）、強調する1数値の `highlight`（`label` `unit` `value` `dir` `note` `icon`）。**予想と結果がそろう指標が無い日は省く** |
| `reaction` | 反応の図。`lead`、`root`（`text` `sub`）、`mid`（2つ、`text` `sub` `icon` `dir`）、`leaves`（3つ、同じ形） |
| `rates` | 金利の2枚。`title` `lead`、`cards`（`ref` `name` `caption`）、右の解説 `note`（`title` `text`、5行まで） |
| `gold` | 金の天秤。`title` `lead`、上がる側（軽い）の `light`、下がる側（重い）の `heavy`（各 `ref` `name`、または `name` `dir` だけ）、`sub_price`、結論の `conclusion`（2行まで）。価格は snapshot の XAU を使う |
| `table` | 主要マーケットの数字。`ref` `name` を10行前後。左右2列に半分ずつ並ぶ |
| `movers` | 注目銘柄の帯。`title`、`items`（`ref` `note`。2つまで） |
| `bias` | `label`（例「ややリスクオフ」）、`dir`、`text`（5行まで） |
| `watch` | 注目点3つ。`icon` `title` `text`（2行まで）。Market Bias の監視項目と同じ内容 |

icon は gold / bank / dollar / chip / bond / oil / calendar / chart。ブロック（`focus` `reaction`
`rates` `gold`）は省けて、番号は出したものだけで振り直される。見出し・中見出しは `thumb` の
`title` / `sub` を使う。

- 収まらない文言・行数オーバー・引けない `ref` は**エラーで止まる**。文言を詰めて通るまでやり直す
- **人物の発言・似顔絵を入れない。**原稿に無い要素を図解だけに足さない
- 画像は `note/info_YYYYMMDD.png`。原稿と一緒にコミットする。push 後
  `https://teiten.trade/info/YYYY-MM-DD.png` で開ける

**週次も同じスクリプトで出す。**`node tools/make-infographic.mjs YYYY-wNN` → `note/info_YYYYwNN.png`
（`https://teiten.trade/info/YYYY-wNN.png`）。`ref` は `snapshot` の代わりに `performance` を引き、変化は前週比になる。
見出しの言葉が「今週の資金フロー」「Market Bias（来週）」「来週の注目ポイント」に変わるほかは日次と同じ。
`watch` には `schedule` にある予定だけを書く。シナリオの3案は図解にも入れない（サイトに残す）。

## やってはいけないこと

- **数値を創作しない。**出典が確認できない値は載せない
- **個別の売買推奨を書かない。**投資助言・代理業の登録がないため、情報提供と分析にとどめる
- **架空のサンプルを本番ディレクトリに置かない。**レイアウト確認が必要なら `draft: true` にする
- **配信頻度について実態と違う主張をしない。**メール配信は未開始なので「配信」ではなく「更新」と書く

## 週次まとめ

週末に「今週の総括」と「来週の備え」を出す。日次の積み上げを束ね直すもので、**個別の値動きではなく資金の移動として何が起きたか**を整理する。

### 金曜の米国セッションは日次に無い

日次は「D日の記事が D-1日の米国セッションを扱う」規約なので、**金曜の米国セッションを扱う日次は翌週の月曜まで存在しない。**土曜朝の週次は、週の最終日を日次から拾えない。

土曜9:00 JST の時点で金曜の米国市場（土 05:00 JST 引け）は閉じているため、**データそのものは取れる。金曜分だけは週次が自分で調べる。**週を締めるのに最も重要な一日なので、ここを落とすと総括にならない。

翌週の月曜の日次は、この金曜分をあらためて日次として扱う。重複ではなく、粒度が違う。

### 手順

```bash
python tools/should-run.py --kind weekly   # 休止期間かを確認
python tools/fetch-weekly.py --write       # 週の数値を一括で取り、src/data/weekly/YYYY-wNN.json に書く
python tools/new-weekly.py                 # 直近に終わった週。performance に取得値が入る
python tools/new-weekly.py 2026-09-14      # その日を含む週
```

**`fetch-weekly.py` を `new-weekly.py` より先に実行する。**順番が逆だと performance の値が空の雛形になる
（そのときは雛形を消して作り直す）。

週番号・対象期間（月〜金）・来週のスケジュール枠は日付から自動で出る。**手で書かない。**その週の日次レポートが何本あるかも表示されるので、材料が足りなければ書くのを見送る判断ができる。

### 週の数値（`tools/fetch-weekly.py`）

2026-10-27 から、週次は**日次の寄せ集めではなく、週単位でしか出ないデータの置き場**にした。
銘柄を9から25に増やし、手で寄せ集めると割れと捏造の危険も増えるので、**取れる系列はすべて機械で取る。**

| 出すもの | どこに出るか |
|---|---|
| 25銘柄の週末値と前週末比（貴金属・金利・為替・商品・株・Crypto・Vol・クレジット） | 雛形の `performance` に入る。**書くのは `note` だけ** |
| レシオ3本（金/銀・金/原油・金/銅）と直近20週の推移 | サイトが JSON から描く。記事には `ratioNotes` に一言だけ書く |
| CFTC 建玉（金・銀・原油・円、4週）、BTC現物ETFの週間フロー、FOMC の織り込み（FF金利先物から算出） | サイトが JSON から描く（「ポジションとフロー」） |
| 週次相関（金 × 実質金利・DXY・Nasdaq・BTC、直近8週） | サイトが JSON から描く |
| 週足のレンジ（金・銀・ドル円の高値・安値） | サイトが JSON から描く。`moreLevels` と予想レンジの根拠に使う |

**JSON を手で書き換えない。**`performance` の value・change・dir・status も書き換えない。
`check-report.py` が JSON と突き合わせ、違えばエラーにする。スクリプトの値と報道が食い違っても、系列の値を採る
（`docs/SOURCES.md` §1）。食い違いが大きく本文で触れる必要があれば、本文に両方を書く。

**定義の注意**（本文を書くときに取り違えやすいもの）：

- `△ ◯◯：2026-10-22 時点の値です` と出た行は、金曜分がまだ公表されていない。**本文にその日付を添える**
- `status: 読み取り` の行は金曜の値がまだ確定していない（先物とドル指数の金曜の足は土曜13時 JST に確定する）。
  **「終値」と書かない。**サイトには「読み取り」の札が付く
- `限月交代の週。前週比は同じ限月どうしで出した` と出た行は、本文の寸評に限月を書く
- 円建て金は「金（USAGOLD）× ドル円（NY17時）」の算出値（1トロイオンスあたりの円）。国内の店頭小売価格（1グラムあたり、税込）とは別物
- FOMC の織り込みは FF金利先物からの**算出値**。報道が「CME FedWatch によると◯%」と書く値とは少しずれる。
  本文で「約8割」と書くなら、どちらの値かを明記する
- レシオ・相関・週足のレンジは COMEX 先物から出す。金の performance（USAGOLD 現物）とは水準が少し違う

**レシオの一言（`ratioNotes`）の型**：上がった・下がったを書くだけでなく、何を意味するかまで書く。

- 金/銀が上がる週 … 不安の買い（金だけが買われた）か、換金売り（銀のほうが売られた）
- 金/銀が下がる週 … 商品全体の買い
- 金/原油が下がる週 … 原油の供給・インフレの材料が強い
- 金/銅が上がる週 … 景気への不安、下がる週 … 景気への期待

**`flows` に書くもの**：金ETF（GLD）・銀ETF（SLV）の保有量の週間変化。World Gold Council・SPDR・iShares の公式ページか、
複数の報道で確かめた値だけ。確かめられなければ `status: 未確認` のまま値を空にする。**建玉・BTC現物ETF・FOMC の織り込みは書かない**（JSON から出る）。

`fetch-weekly.py` で取れなかった銘柄は、その行が `status: 未確認` で値の空いた状態で入る。報道を複数社で突き合わせて
値が決まれば、value・change・dir を書き、`status` を消す（`check-report.py` は警告を出すので、本文に出所を書く）。決まらなければ未確認のまま。

検査は日次と同じコマンドで通る。

```bash
python tools/check-report.py 2026-w38
```

### frontmatter の週次固有項目

| 項目 | 役割 |
|---|---|
| `year` / `week` | ISO週番号。ファイル名 `YYYY-wNN.md` と一致していること |
| `start` / `end` | 対象期間。月曜〜金曜が通例 |
| `points` | 今週の要点。3〜5件 |
| `performance` | **各資産の週次パフォーマンス。週次の主役。**値・変化率・`dir`・`status` は `fetch-weekly.py` の取得値（雛形に入る）。`note`（寸評）を必ず書く。数字だけでは何が起きたか伝わらない。寸評は全行でなくてよいが、金・銀・米2年・米10年・ドル指数・ドル円・原油・日経・BTC には書く |
| `ratioNotes` | 週のレシオへの一言。キーは `gold_silver` / `gold_oil` / `gold_copper` |
| `flows` | 金ETF・銀ETFの保有量など、スクリプトで取れないフロー。確かめられなければ `status: 未確認` |
| `moreLevels` | 銀・ドル円のテクニカル・レベル。`levels`（金）と同じ形式を銘柄ごとに |
| `schedule` | 来週の主要スケジュール。日付ごと。`key: true` で★が付く。**対象期間内の日付を入れない**（来週の予定を書く欄） |
| `levels` | テクニカル・レベル（週末時点）。日次と同じ形式。今週どこが効いて来週どこを見るかの water mark |
| `scenarios` | **来週のシナリオ。週次の看板要素。**bull / base / bear の3案を必須とし、`trigger`（発動条件）・`chain`（因果連鎖）・`target`（価格目処）を同じ粒度で書く |
| `bias` | 来週のスタンス。記事の結論として独立したブロックに出る |
| `thumb` | note 用サムネイルの文言。日次と同じ形（「8-B. note用のサムネイルを書き出す」）。`node tools/make-thumb.mjs YYYY-wNN` で `note/thumb_YYYYwNN.png` が出る |
| `infographic` | note 用の図解の文言。日次と同じ形（「8-C」）。`node tools/make-infographic.mjs YYYY-wNN` で `note/info_YYYYwNN.png` が出る |

`performance` は雛形の25行をそのまま残す（第44週から。`check-report.py` が欠けた銘柄を警告する）。
並び順も変えない。**金の行を先頭に置く。**`thumb` と `infographic` は label の部分一致で先頭から引くため、
円建て金（XAU/JPY）が先に来ると「XAU」がそちらに当たる。

`infographic.table` は必ず書く。省くと performance の全25行が表になり、縦に収まらない。

`tags` には、本文や寸評で論点にした銘柄のトピック名を付ける：`銀` / `プラチナ` / `銅` / `円建て金` / `ユーロドル` /
`米2年債` / `COT` / `クレジットスプレッド`（説明文は `src/config.ts` の `TOPICS`）。**表記を揺らさない。**
「ユーロ/ドル」「EURUSD」と書くと別のトピックが立つ。

### 本文の構成

```
## 週の核心テーマ
## 今週の主要イベント振り返り   （### ①②③ で個別に）
## 今週の資金フロー構造          （第一の流れ／第二／第三）
## 来週の備え（M/D〜M/D）
   ### 最重要イベント
   ### 国内政治・政策の波乱要因
   ### 地政学シナリオ
   ### 日経・円の焦点            （予想レンジの上限・下限を明記）
   ### 金・銀・ドル円の焦点        （3本とも予想レンジの上限・下限を明記。週足のレンジとテクニカル・レベルを根拠に）
```

レシオ・ポジションとフロー・週次相関・週足のレンジはサイトが JSON から描くので、本文で数値を並べ直さない。
**「今週の資金フロー構造」の根拠として引用する**（「金/銀レシオが74.6へ上昇し、銀のほうが売られた」「投機筋の金の買い越しは4週続けて減った」）。

**ゴールドシナリオは本文に書かない。**`scenarios`（frontmatter）に構造化して入れる。散文にすると3案の比較ができず、翌週にどれが起きたかを検証できない。

`start`〜`end` の期間に該当する日次レポートは、詳細ページが自動で逆引きして並べる。本文で個別に列挙しなくてよい。

分析の枠組みは `money-flow-report` の `references/weekly-format.md` にも従う。

### note用の簡易版

**週次も日次と同じく note を出す。**`note/YYYY-wNN.md` に置く。線引き・書式制約・免責・分量（サイト版の3〜4割）は日次の「8. note用の簡易版を書き出す」と同じ。

- 冒頭の大・中・小タイトル。小タイトルは「定点観測 週次まとめ 第NN週」
- 節は「今週の資金フロー」（総括の連鎖を太字1行＋本文）→「今週の数字」（`performance` のうち金・銀・米10年・ドル指数・ドル円・WTI・日経・BTC の値と変化を箇条書き。全25行は並べない。未確認は未確認と書く）→「今週の論点」（2つまで）→「Market Bias（来週）」（`bias` と監視項目3つ）→「続きはサイトで」
- **シナリオの3案・テクニカル・レベルの全段・来週の予定の全件・出典はサイトに残す**
- 末尾のリンクは `https://teiten.trade/weekly/YYYY-wNN/`
- 書き上げたら、本文をそのままチャットに出力する
