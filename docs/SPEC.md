名前は定点観測から採っている。**同じ指標を、同じ形式で、毎営業日記録する**という運用がそのまま編集方針であり、機能設計の前提でもある。スナップショットの項目や記事構成を頻繁に変えない理由はここにある。

### 法務上の制約

投資助言・代理業の登録がないため、**個別の売買推奨はできない**。レポートは情報提供・分析にとどめ、免責を全ページのフッターに固定表示する（`src/config.ts` の `DISCLAIMER`）。

**有料化で問われるのは対価の名目ではなく、売り方と個別性である。**金融庁の監督指針（Ⅶ-3-1(2)②イ）は、会員登録等を行わないと投資情報等を購入・利用できない（単発での購入を受け付けない）場合と、個別・相対性の高い提供には登録が必要になるとしている。会員制は保留中。再開する場合は、仕組みを作る前に登録の要否を財務局または弁護士に確認する。詳細は `docs/STRATEGY.md` §4。

金融情報は YMYL 領域にあたるため、発行元・発行日・出典の明示が検索評価に直結する。

**注意：コンテンツのキャッシュ**

Astro 5 はコンテンツのレンダリング結果をキャッシュする。置き場は `.astro/` だけでなく **`node_modules/.astro/`** にもあり、次の場合に実態とビルド結果がずれる。

- `astro.config.mjs` や `src/remark-flow.mjs` を変更した → 変換が反映されない
- **記事ファイルを削除した → 削除したはずのページが生成され続ける**

どちらも次で解消する。

```bash
rm -rf .astro dist node_modules/.astro node_modules/.vite
npm run build
```

`.astro` だけ消しても足りない。実際に、削除した週次記事が `node_modules/.astro` 側のキャッシュから復活した。Cloudflare は毎回クリーンな環境でビルドするので、本番では起きない。

## 5. コンテンツモデル

### reports（デイリーレポート）

ファイル名がそのままURLになる。`src/content/reports/2026-09-22.md` → `/reports/2026-09-22/`
アンダースコア始まりのファイル（`_TEMPLATE.md`）はビルドに含まれない。

| フィールド | 型 | 役割 |
|---|---|---|
| `no` | number | 号数。マストヘッドと記事冒頭の通し番号 |
| `title` | string | 見出し |
| `deck` | string | リード文。TOPのヒーローと一覧の抜粋に出る |
| `date` | string | 発行日 `YYYY-MM-DD` |
| `updated` | string? | 更新時刻の表示用 |
| `points` | string[] | 本日の要点。3〜5件。TOPのサイドバーと記事冒頭に `01..` と並ぶ |
| `snapshot` | Quote[] | マーケット数値。**最上部のティッカーにも同じ値が流れる** |
| `headline` | {value, dir}? | 一覧の右端に出す代表値（通常は XAU/USD の変化率） |
| `thumb` | object? | note 用サムネイルの文言（`title` / `sub` / `bias` / `notes`）。サイトには出ない。数値は持たず `snapshot` から取る |
| `infographic` | object? | note 用の図解の文言（`flow` / `quotes` / `focus` / `reaction` / `rates` / `gold` / `table` / `movers` / `bias` / `watch`）。サイトには出ない。各項目の数値は `ref` で `snapshot` と `quotes` から引く。形は SKILL.md の「8-C」 |
| `levels` | Level[] | テクニカル・レベル。`{kind, value, note}`、`kind` は resistance / current / support。**定点観測の中核**。同じ水準を毎日追うことで、どこが効いてどこが抜けたかが時系列で見える |
| `tags` | string[] | トピック索引に使う |
| `description` | string | SEO用。未記入なら `deck` が使われる |
| `keywords` | string[] | 予備 |
| `ogImage` | string? | 未指定なら `/og-default.png` |
| `draft` | boolean | `true` はビルドに含めない |
| `unlisted` | boolean | 一覧・サイトマップに出さず noindex。URLでは見られる |
| `access` | `public` \| `members` | クローズ化フェーズ用。現状は `public` のみ運用 |

`Quote` は `{ label, value, change, dir }`。`dir` は `up` / `down` / `flat` で数値の着色に使う。`value` と `change` は文字列（"4.118%" "−3.2bp" のように単位がまちまちで、計算せず表示するだけのため）。

### weekly（週次まとめ）

`src/content/weekly/2026-w38.md` → `/weekly/2026-w38/`

日次と共通の項目（`title` / `deck` / `points` / `tags` / `description` / `draft` / `unlisted` / `access`）に加えて、週次固有の項目を持つ。

| フィールド | 型 | 役割 |
|---|---|---|
| `year` / `week` | number | ISO週番号。ファイル名と一致させる |
| `start` / `end` | string | 対象期間。月曜〜金曜が通例 |
| `performance` | Row[] | 各資産の週次パフォーマンス。`{key?, group?, label, value, change, dir, status, note}`。**日次の `snapshot` と違い寸評（`note`）を持つ**。1週間を振り返る記事では数字だけでは何が起きたか伝わらないため。第44週から25銘柄を `group`（metals / rates / fx / commodities / equities / crypto / vol / credit）で束ねて表示する。`key` のある行は `check-report.py` が JSON の取得値と突き合わせる。`status` は 確定 / 読み取り / 未確認（未確認は値を空にし、表示が「未確認」と出す）。`group` の無い第43週までの行は label から推定してグループに入れる |
| `ratioNotes` | Record | 週のレシオ（金/銀・金/原油・金/銅）への一言。数値は JSON から出る |
| `flows` | Flow[] | スクリプトで取れないフロー（金ETF・銀ETFの保有量）。`{label, value, change, dir, status, source, note}` |
| `moreLevels` | {asset, levels}[] | 金以外（銀・ドル円）のテクニカル・レベル |
| `schedule` | Day[] | 来週の主要スケジュール。`{date, items:[{label, key}]}`。`key: true` で★が付く |
| `levels` | Level[] | テクニカル・レベル（週末時点）。日次と同じ形式 |
| `scenarios` | Scenario[] | 来週のシナリオ。`{kind, trigger, chain, target}`、`kind` は bull / base / bear。**週次の看板要素**。散文にすると3案の比較ができず、翌週の検証もできない |
| `bias` | string | 来週のスタンス。記事の結論として独立したブロックに出る |
| `thumb` / `infographic` | object? | note 用のサムネイルと図解の文言。日次と同じ形で、数値は `performance` から取る。サイトには出ない |

詳細ページは `start`〜`end` の期間に該当する日次レポートを自動で逆引きして並べる。

**週次の機械取得データ（`src/data/weekly/YYYY-wNN.json`）**：`tools/fetch-weekly.py --write` が書く。25銘柄の週末値と前週末比、
レシオ3本と直近20週の推移、週足のレンジ（金・銀・ドル円）、CFTC 建玉（金・銀・原油・円、4週）、BTC現物ETFの週間フロー、
FOMC の織り込み（FF金利先物から算出）、週次相関（金 × 実質金利・DXY・Nasdaq・BTC、直近8週）を持つ。
**週のレシオ・ポジションとフロー・週次相関・週足のレンジは、frontmatter を経ずにこの JSON から直接描く。**
同じ数字を2か所に書くと片方だけ直した号が出るため（thumb と同じ理由）。JSON が無い週はこれらの節を出さない。
第39〜43週の JSON は 2026-10-27 に遡って作った（機械取得の値だけで、本文・performance は変えていない）。

### world（世界の定点）— 設計済み・未実装（2026-10-30）

`src/content/world/2026-w45.md` → `/world/2026-w45/`。**週次から始め、形が固まったら日次に移す**（段階は後述）。

**何をするページか。**6つの地域の窓（北米・欧州・ロシア・中国・インド・中東）を固定し、**毎回同じ形で2つの層を観測する。**

- **論調の層**：同じ3つの問い（金・ドル・米金利を、その週どう説明しているか）を各地域の媒体から読み、論調（強気・中立・弱気）をログに残して翌週に答え合わせする
- **現物の層**：その地域の金の実需を表す**固定した系列を1本だけ**置く（金ETF保有量・上海プレミアム・インドの小売価格差など）。媒体の記事からは取らず、機械で取る

「観測点を固定する」という媒体の方針を、銘柄の軸から地域の軸へ広げたもの。日次・週次が「何が起きたか」を扱うのに対し、
このページは「どこで、どう読まれ、現物はどう動いたか」を扱う。2層にするのは、**「論調は強気だが現物は売られている」という食い違いがそのまま記事の材料になる**ため。
論調だけでは印象の記録に留まり、現物だけでは週次の数表と変わらない。
当初は論調のページ（A）と現物フローのページ（B）を別に考えたが、軸が同じなので1つにした（2026-10-30）。

媒体の取得元は `docs/research/overseas-market-media-top50.md`（AI が実際に取りに行ける 50 媒体。2026-10-30 に全件 fetch で確認）に限る。

**frontmatter に数値は書かない。**論調の層に入るのは論調と要約と出典だけ。現物の層の値と、金・ドル指数・米10年の値は、
`src/data/world/<slug>.json` と `src/data/weekly/<slug>.json` から描く。6 媒体の記事から数字を拾わせると、`SOURCES.md` §1 の「系列を1つに固定する」が崩れる。

| フィールド | 型 | 役割 |
|---|---|---|
| `year` / `week` / `start` / `end` / `title` / `deck` / `date` / `tags` / `description` / `draft` / `unlisted` / `access` | | 週次と同じ |
| `windows` | Window[] | **6件固定・順序固定**：`na`（北米）/ `eu`（欧州）/ `ru`（ロシア）/ `cn`（中国）/ `in`（インド）/ `me`（中東）。`{ region, media: [{name, url}], gold: Take, dollar: Take, rates: Take, quote?: {text, source, url}, status }` |
| `Take` | object | `{ stance, summary }`。`stance` は bull / neutral / bear / **split** / **unknown**、`summary` は全角 80 字以内の自分の言葉。**翻訳の転載ではない**。`split` は 1 窓 2 媒体で向きが逆のとき（中立に丸めない。summary に両方の読みを書く）。`unknown` はその論点の記事が無かったとき（summary は理由 1 行。「今週の該当記事なし」等） |
| `windows[].quote` | object? | 原文の短い引用。30語（日本語なら 60 字）以内、出典 URL 必須。無くてよい |
| `windows[].status` | enum | 確定 / 未確認。`確定` は 3 論点のうち 1 つ以上の論調が取れた窓、`未確認` は 3 論点とも `unknown` の窓（`gold` 以下は書かない）。**論点ごとの欠けは `stance: unknown` で表し、近い媒体や検索結果で埋めない** |
| `physicalNotes` | Record | 現物の層への一言。キーは地域コード（`na` …）。**値は書かない**（週次の `ratioNotes` と同じ扱い）。JSON に値が無い窓は書かない |
| `review` | object | 前週の論調の答え合わせ。`{ of: '2026-wNN', items: [{ region, topic, stance, result, note }] }`。`topic` は gold / dollar / rates、`result` は hit / partial / miss / pending。**判定は機械で行う**（下記） |
| `thumb` / `infographic` | object? | 当面は持たない。note 用の図解は論調の分布（6×3）と現物の6本を描く形を後で決める |

**現物の層の系列（`src/data/world/<slug>.json`）。**`tools/fetch-world.py --write` が書く。窓ごとに1本、系列は `SOURCES.md` に登録したものだけを使う。
周期が週次から四半期までばらつくので、**値には必ず「◯月分」「◯/◯時点」を添え、遅れを理由に空欄にしない**（SOURCES.md §2「遅れの扱い」と同じ）。
取れなかった系列は `未確認` で、近い数字で埋めない。

| 窓 | 系列 | 周期 | 取得元 | 状態（2026-10-30） |
|---|---|---|---|---|
| `na` 北米 | 金ETF（GLD）保有量 | 週次 | 週次の `flows` と同じ出所 | **今すぐ使える**（既に週次で扱っている） |
| `eu` 欧州 | スイスの金の輸出入（仕向地別） | 月次 | 連邦関税・国境安全保障庁の統計 | 取り方の確認が要る |
| `ru` ロシア | ロシア中銀の金準備 | 月次 | ロシア中銀の公表値 | 取り方の確認が要る |
| `cn` 中国 | 上海プレミアム（SGE 基準価格と LBMA の差） | 週次 | 上海黄金交易所の基準価格と USAGOLD の金 | 取り方の確認が要る。媒体の記事の「プレミアム」を転記しない |
| `in` インド | 国内小売価格（24K）と国際価格の差 | 日次 | Goodreturns の小売価格（2026-10-30 に fetch 可を確認）と USAGOLD の金、ドルルピー | **今すぐ使える**。GST 等を含まない指標値である旨を添える |
| `me` 中東 | 湾岸の中銀の金購入 | 四半期 | World Gold Council（Goldhub。fetch 可） | 四半期分を「◯Q分」として置く |

系列の登録（取得元・定義・遅れ・注意）は `docs/SOURCES.md` に節を足してから行う。**登録していない系列の値を JSON に書かない。**

**論調の判定規則。**`review` は人の印象ではなく、`src/data/weekly/<slug>.json` の前週比で判定する。
金・ドル指数は ±0.5%、米10年は ±5bp を閾値にして、閾値を超えた上昇は bull、下落は bear、閾値内は neutral が hit。
方向は合ったが閾値内なら partial、逆なら miss。期限の無い論調なので pending は使わない（週が閉じれば必ず判定できる）。
`stance` が `split` / `unknown` の論点は判定しない（`items` に入れない）。割れた窓でどちらの媒体が当たったかは、判定ではなく本文で書く。
判定は `tools/review-world.py <YYYY-wNN>` が前週の `world` と当週の JSON から機械で出し、
`check-report.py` が `review` の中身と突き合わせる。**手で書いた判定を優先しない。**
現物の層は答え合わせの対象にしない（予想ではなく実績のため）。代わりに、論調と現物の向きが食い違った窓を本文で取り上げる。

**論調の取得元（主／代替）。**主が取れなければ代替、代替も取れなければ `未確認`。これ以外の媒体を使わない。
一覧は `src/config.ts` の `WORLD_SOURCES` に置き、`check-report.py` が `media[].url` のホストをこの一覧と突き合わせる。

**書き方の線引き。**要約は自分の言葉、引用は短く出典つき、売買の推奨は書かない（§1 の法務上の制約はそのまま）。

記事 URL の日付（無ければ本文の日付）で週を決め、金曜の米国セッション後の記事（JST 土曜早朝）は含め、実行後に出た記事は翌週に回す。

**ページ（`/world/<slug>/`）の並び。**要点 → 6 つの窓（カード。上段に地域名・3 つの論調タグ・要約・出典リンク、下段に現物の定点の値・前回比・時点・一言。

**日次の snapshot・ティッカー・週次の 25 銘柄は変えない。**

**定期実行。**週次（土曜 14:00 JST）の手順に 7-D として相乗りし、別のルーティンは作らない（同じ対象週を使うため）。
7-D は (1) `tools/fetch-world.py --write` で現物の層を取る（`src/data/world/<slug>.json`。手で書き換えない）→ (2) `WORLD_SOURCES` の主 6 本を fetch →
(3) 取れなかった窓だけ代替を fetch → (4) `tools/new-world.py` の雛形に `windows` と `physicalNotes` を書く →
(5) `tools/review-world.py` で前週の判定を出し `review` に入れる → (6) `check-report.py <YYYY-wNN>` → (7) `draft: true` のまま push（JSON も add に含める）。
週次本体が「休止」なら 7-D も出さない。**週次本体の push と同じコミットにする**（片方だけ出た週を作らない）。

**段階。**
0. 2026-10-30 に第44週で 1 本試作した（`docs/research/world-sample-2026-w44.md`。ビルド対象外）。6 窓を実際に fetch し、5 窓が確定・インドが未確認。上の `split` / `unknown`、取得元の注意、時刻の基準はこの試作で足した
1. **第45週（11/7 土）から週次で開始。論調の層だけで出す。**初回は人が手で 1 本作って形を固め、定期実行に 7-D を足すのは第46週から。現物の層は「未確認」ではなく節ごと出さない（JSON が無い週は描かない。週次のレシオと同じ扱い）
2. **現物の層は、取れる系列から順に足す。**先に北米（GLD）とインド（小売価格差）。次に `SOURCES.md` に登録したうえで中国（上海プレミアム）・欧州（スイス税関）・ロシア（中銀準備）・中東（WGC）。6 本揃うまでは、揃った窓だけ下段を出す
3. 日次への移行は、4 週連続で `unknown` の論点が 18 マス中 3 つ以下（`未確認` の窓なら 1 つ以下）、かつ `review-world.py` の判定が人の読みと食い違わない状態が続いてから。日次に移すのは論調の層だけで、現物の層は系列の周期に合わせて週次のまま置く。日次ルーティン（8:00）の負荷を見て、窓を 6 から減らさず fetch を主 6 本に限る

## 8. 公開制御

`IS_PUBLIC` が唯一のスイッチ。`false` のあいだは全ページ noindex、サイトマップと RSS も出力しない。

**本公開の手順（2つをセットで行う）**

1. `src/config.ts` の `IS_PUBLIC` を `true` にする
2. `public/_headers` の `X-Robots-Tag: noindex, nofollow` の行を削除する

片方だけだと、サイトマップを出しているのに noindex ヘッダが付いた状態になり、Search Console でエラーになる。

`robots.txt` と `_headers` の両方で止めているのは、robots.txt がクロールを止めるだけで、外部リンク経由のインデックス登録を防げないため。

## 9. SEO要件

**新規ページを作るときは、以下を満たすこと。** `Base.astro` に props を渡せば大半は自動で処理される。

### 必須

| 項目 | 実装 |
|---|---|
| `title` | `Base` の `title`。`「ページ名 \| TEITEN（定点）」` に自動整形される |
| `description` | `Base` の `description`。**80〜100字**を目安にする |
| canonical | 自動。`SITE_URL` + パス |
| H1 | **1ページ1個**。TOPのみマストヘッドがH1（`isHome`）で、媒体名だけでなくタグラインまで含める。他はページ見出しがH1 |
| 見出し階層 | H1 → H2 → H3。スキップしない |
| パンくず | `Base` の `breadcrumbs` に `[{name, path}]` を渡す。ホームは自動で先頭に付く。画面側のパンくずも別途置く |
| 構造化データ | `WebSite` と `Organization` は全ページ自動。記事は `Base` の `schema` に `NewsArticle` を渡す |
| 日時 | `article:modified_time` と `dateModified` は **ISO8601（`+09:00` 付き）**。表示用の `updated` をそのまま渡さない。`lib/content.ts` の `isoJst()` で変換する |
| 恒久 noindex | 検索結果に出したくないページは `Base` に `noindex` を渡す（404 など）。`IS_PUBLIC` とは別系統 |
| 外部リンク | 本文（Markdown）は `rehype-external-links.mjs` が `target="_blank"` と `rel="noopener noreferrer"` を自動付与する。`.astro` に直接書いた外部リンクは対象外なので手で付ける |
| OG画像 | 未指定なら `/og-default.png`。記事固有なら `ogImage` |
| `lang` / charset | `Base` が `ja` / UTF-8 を出力 |

### description の文字数について

診断基準は120〜160字を推奨しているが、**日本語では80〜100字を採用している。** Google の検索結果は日本語で80〜90字程度で切られるため、120字以上書いても後半は表示されない。英語基準をそのまま適用していない点は意図的な逸脱。

### 構造化データの方針

`@graph` に束ねて1本の JSON-LD として出す。`@id` で相互参照させることで、ページをまたいで同じ `WebSite` / `Organization` を指していることを検索エンジンに伝える。

- 全ページ：`WebSite` + `Organization`
- 下層ページ：`BreadcrumbList`
- 記事：`NewsArticle`（`headline` / `datePublished` / `author` / `publisher` / `image` / `keywords` / `isAccessibleForFree`）

### 計測タグと告知の連動

GA4 に関する記述は `GA4_MEASUREMENT_ID` の有無に連動させてある。**IDを入れれば計測と告知が同時に有効になり、外せば同時に消える。**実態と記述が食い違わないようにするための作りなので、この条件分岐を外さないこと。

同種の連動は購読導線（`SUBSCRIBE_ENABLED`）と公開制御（`IS_PUBLIC`）にもある。設定値ひとつで、機能と表示と告知がまとめて切り替わる状態を保つ。

### 禁止事項

- **装飾目的で `<s>` を使わない。** 取り消し線の意味を持つ。区切り線は `<span class="rule">`
- **見出しレベルを飛ばさない。** 一覧を並べるページでは、`ReportRow`（h3）の前に必ず `.sec-head` の h2 を置く
- **`description` を使い回さない。** 未指定だと `SITE_DESCRIPTION` が入り、ページ間で重複する
- 画像を追加したら必ず `alt` を書く。装飾画像は `alt=""` と `aria-hidden="true"`
- 外部リンクに `target="_blank"` を付ける場合は `rel="noopener"` を併記する

### アクセシビリティ

- `prefers-reduced-motion` に対応済み（ティッカーの流れとカードの浮きが止まる）
- スキップリンクを `Base` に設置済み
- グリッド／フレックスの子要素には `min-width: 0` が必要（`global.css` のリセットで全要素に適用済み）

#### /admin（スマホ・外出先向け）

GitHub API 経由で `draft` を書き換えてコミットする。ローカルのクローンもPCの

**認証は Cloudflare Access。**ただし `*.pages.dev` へ直接叩かれる経路が残るため、

ヘッダの有無だけを見る実装にはしていない（ヘッダは呼び出し側が付けられる）。
**環境変数が未設定なら誰も通さない**（fail closed）。

必要な環境変数（Cloudflare Pages の設定画面で登録する）

| 変数 | 内容 |
|---|---|

`/admin` 配下に置いてあるので、この1本で両方を覆える。

**検査について**：Worker 上では Python が動かないため、`check-report.py` を
そのまま呼べない。`functions/admin/_lib.ts` に**公開の可否に直結する項目だけ**を

そちらを通している。TS版は「壊れた下書きを公開させない」最後の砦という位置づけ。
**両方を直すときは片方だけ直さないこと。**

`/admin` は恒久 noindex で、サイトマップからも除外している（`astro.config.mjs` の
`ALWAYS_EXCLUDED`）。

#### tools/admin.py（ローカル向け）

```bash
python tools/admin.py   # http://127.0.0.1:4399 が開く
```

日次の定期実行は、条件を満たした号を公開状態で push する（下の「日次の自動公開」）。
条件を満たさなかった日次と、週次は `draft: true` で push されるので、この画面で内容を確認して公開する。
公開済みの号を非公開に戻すのもこの画面で行う。Markdown を直接編集しなくてよい。

- 日次・週次を新しい順に一覧し、状態（下書き／公開中）と検査結果を表示する
- **検査が通らない記事は「公開する」を押せない**。エラーの内容もその場に出る
- 「公開する」で `draft: false` にし、検査を再実行し、通れば commit と push まで行う。
  通らなければ `draft: true` に戻して中断する
- `127.0.0.1` にのみバインドする。外部には公開されない

### 日次の自動公開

日次は 8:00 に定期実行が始まり、**条件を満たせば人の確認を待たずに公開状態で push する**
（公開は 8:15 前後）。問題があれば人があとから `/admin` で非公開に戻す。
**大きな問題がありそうな号だけは、従来どおり下書きで止める。**

| 判定するもの | 置き場所 | 内容 |
|---|---|---|
| 機械で分かる条件 | `tools/publish-gate.py` | 検査のエラー、発行日が今日（JST）でない、snapshot が8件未満、主要5指標（金・ドル指数・米10年・WTI・S&P 500）の未確認、snapshot の未確認が3件以上、`review` の欠落 |
| 書き手の判断 | `docs/ROUTINES.md` の「公開の判定」節 | 主要な数値の出所が食い違ったまま、1件の要約にしか頼れなかった、過去の号の誤りを見つけた、手順が失敗したまま、自信が持てない点が残る |

- `draft:` の行は `publish-gate.py --apply` だけが書き換える。定期実行に手で書き換えさせない
- 公開状態にした号でビルドが落ちたら `--hold` で下書きに戻す
- **この判定は数値が正しいことを保証しない。**機械が見るのは「取れているか」までで、
  もっともらしい誤った数字は通る。公開後に人が読んで、誤りがあれば非公開に戻すか訂正する
  （訂正の形は「数値の扱い」）
- 週次は自動公開しない（金曜の米国セッションを日次の裏づけなしに自分で調べる号で、誤りの余地が大きい）

### 数値の扱い

- 出典が確認できない数値は載せない
- 取得できなかった指標は「未確認」と明記する。推測で埋めない
- 出典は素のURL列挙ではなくリンク付きリストで書く（note向けの書式をそのまま持ち込むと1段落に潰れる）
- **スクリプトで取れる系列の値と、報道の同じ定義の値が食い違ったら、系列の値を採る**（`docs/SOURCES.md` §1）
- 取得元は `docs/SOURCES.md` が原本。公開版は `/sources/`（`src/pages/sources.astro`）。**片方だけ直さない**
- **公開済みの号の数値を直すときは、本文冒頭に「訂正（日付）」の注記を置き、当初の記述を残す。**黙って書き換えない。値だけ入れ替えると分析と食い違うので、その値に基づく文章も書き直す。未確認だった値を埋めるだけ（差し替え）の場合は注記は要らない

## 本書の更新について

サイトの構造・設計判断・運用ルールを変えたら、本書も同じコミットで更新する。「更新履歴」には**何をしたか**だけでなく、**なぜそうしたか**が分かる粒度で書く。半年後に読み返して判断を再現できることが目的である。
