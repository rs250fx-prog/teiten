エグゼクティブサマリー

「世界の定点」は、TEITEN の編集方針「同じ観測点を同じ形で記録する」を、銘柄の軸から地域の軸へ広げる新コンテンツです。設計と試作は10月30日に完了し、仕様書への反映も済んでいます。実装はまだ着手しておらず、本提案はリリースまでの順番と判断事項を確認するものです。

なぜ今やるか

  • 戦略（STRATEGY §2）は「当面の投資先は広告の配置ではなく、読者の満足度を上げるサイト拡張」と定めている。本件はその拡張に当たる
  • 海外メディアの地域別の読みを横断して毎週同じ形で追う場所は国内に無い。差別化が明確
  • 論調を翌週に機械で答え合わせする透明性が、読者が広告・商材の案内を信用する根拠になる
  • 取得元（50媒体）は実際に fetch して確認済み。週次ルーティンに相乗りでき、新しい定期実行を作らない

「世界の定点」が戦略に果たす役割

差別化

北米・欧州・ロシア・中国・インド・中東の媒体が、同じ週の金・ドル・米金利をどう説明したかを横並びで記録する。国内にこの形の場所は無い。「海外のFX情報 TOP50」の調査（10/30）で、AI が実際に読める媒体を地域バランスで50本確保した

信用の根拠

論調をログにし、翌週に機械で答え合わせする。「数値を創作しない・取得元を開示する・シナリオを答え合わせする」という既存の運用の延長で、読者が広告や商材の案内を信用する土台になる

囲い込み

毎週同じ形で積み上がるので、前週比・前月比の読み方が育つ。日次（何が起きたか）・週次（数表）に対し、本件は「どこで、どう読まれ、現物はどう動いたか」を扱い、既存記事と重ならない

運用コスト

新しい定期実行を作らず、週次（土曜 14:00 JST）の手順に 7-D として相乗りする。1回の fetch は主6本＋代替2本まで。利用量の上限に収まる範囲で設計した

外せない制約

  • 個別の売買推奨を書かない。投資助言・代理業の登録が無い。要約は自分の言葉、引用は短く出典つき
  • 数値を創作しない。窓に数値は書かず、値は週次の JSON と固定系列から描く。6媒体の記事から数字を拾わない
  • 出典を開示する。金融情報は YMYL 領域にあたり、発行元・発行日・出典の明示が検索評価に直結する
  • 取れなかった窓は「未確認」。近い媒体や検索結果で埋めない。読んでいない媒体を出典にしない

編集方針と仕様の要点（下流）

編集方針：2層の定点

6つの窓を固定し、各窓を2段で毎週観測する。論調の層は、その地域の媒体が金・ドル・米金利をどう読んだか。現物の層は、その地域の金の実需を表す固定系列1本。「論調は強気だが現物は売られている」という食い違いが記事の材料になる。当初は別ページだった論調（A）と現物フロー（B）を、軸が同じ6地域なので1ページに合併した（10/30）。

出典アコーディオン仕様への適合

11月6日のコミット a07d624 で、本文の情報元を閉じたアコーディオンにする仕様が入りました（SPEC §7「情報元のアコーディオン」、src/rehype-sources.mjs）。世界の定点はこの仕様の後に実装するため、最初から合わせます。

既存仕様の要点

  • 本文中の「情報元：」だけの段落と直後のリストを、ビルド時に <details class="sources"> に変換する。初期状態は閉じる。執筆側の書式は変えない
  • 見出しは「情報元：媒体名、媒体名、媒体名 ほかN件」。媒体名はリンク文字列の「（」より前を重複を除いて最大3つ。「見出しの媒体数＋N＝リストの行数」
  • JavaScript なし。出典は HTML に最初から含まれる。開閉アニメーションを付けない。印刷では開く
  • 直後がリストでなければ変換しない。check-report.py（原稿）と check-html.mjs（ビルド後、件数の一致）が検査する
  • SEO は Google の公式文書で確認済み（スパムポリシーの違反例に当たらず、モバイルファーストのガイドも省スペースの手段に挙げている）

世界の定点への当てはめ

場所扱い実装の要否
本文末の出典「情報元：」＋リンク付きリスト（「媒体名（記事名、日付）」の形）で書く。rehype が全号に効くので自動で閉じる。SPEC §5 の並びの「→ 出典」を「→ 情報元（§7）」に改める不要SPEC の文言のみ
窓カードの出典リンクfrontmatter（media・quote.url）からページ部品が描く。本文ではないので変換対象外。1窓あたり1〜2本なので、閉じる理由（1号に50行近い出典が本文を切る）が当てはまらず露出のまま不要
第44週の試作「## 出典」の見出しに素の URL を並べており、§7 にも §9「素のURL列挙ではなくリンク付きリストで書く」にも合っていない。雛形（new-world.py）はリンク付きリスト＋「情報元：」で出す要雛形の書式
検査既存の check-report.py・check-html.mjs がそのまま効く。world 用に足すのは窓・stance・ホスト照合などの検査で、出典の形式の検査は共通共通

結論

出典のアコーディオン化は、世界の定点に追加の実装を求めない。本文の書式を既存の規則に合わせ、カードの出典は露出のままにする。この2点を SPEC §5 に1行で明記する。

リスク手当て
